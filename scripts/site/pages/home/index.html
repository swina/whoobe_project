One platform instead of the glue between your CMS, your data and your systems.

Whoobe is a self-hosted platform for content, data and integrations. You configure it instead of coding it, the people who use it need no code, and the security an organisation asks for is part of the product. MIT licence, one organisation per installation, no per-user fee.

Read the documentation Source on GitHub

Run it on your machine

Docker with Compose. The first start takes a few minutes; the script prints the address and the login.

git clone https://github.com/swina/whoobe_project && cd whoobe_project && ./try.sh

./try.sh stop keeps the data, ./try.sh reset deletes everything. For a real installation see the documentation.

Configuration, not glue code

Point the gateway at an OpenAPI file or a sample request: routes, response shapes and fields appear in the editor, and a block can show the data. The credentials stay on the server.

No-code for the people who use it

Editors build pages from blocks, snippets and kits. A data manager adds a field to a class without a deploy.

Security controls, and the proof behind them

An append-only audit log, two-factor authentication by role, single sign-on with OpenID Connect, encrypted credentials. We say what we tested and list what is not covered.
