# Documentation by role

The same documentation, in the order each reader needs it. Each page lists your questions and where the answer is, then a short reading path.
Start with [what Whoobe is](../overview/what-is-whoobe.md) if you have not seen it yet.

| You are | Read | Your first questions |
|---|---|---|
| **CEO, owner, sponsor** | [For the CEO](ceo.md) | Is it a good bet? What does it cost? What are the risks? |
| **IT manager, architect** | [For the IT manager](it-manager.md) | What do we run? How does it fit our estate? What is missing? |
| **DevOps, operator** | [For operators](operators.md) | How do I install, secure, back up, upgrade, monitor it? |
| **Security officer, DPO, compliance** | [For security and compliance](security-and-compliance.md) | What protects it? What is tested? What is open? Where is personal data? |
| **Marketing, content owner** | [For marketing and content](marketing-and-content.md) | What can we do ourselves? What still needs IT? |
| **Data / PIM owner** | [For data owners](data-owners.md) | Can it hold our catalogue? Who sees what? How do we import? |
| **Developer, integrator** | [For developers and integrators](developers.md) | How do I connect a system, consume content, call it from an app? |

All roles: the [full overview](../overview/whoobe-overview.md) has a costed comparison, the list of what Whoobe does **not** do (chapter 4) and a
"is it a fit" checklist; the [design decisions](../architecture/design-decisions/README.md) explain the trade-offs behind the architecture.
